# 武器与钓具开发规范

2026-09-15 · v0.9.2 起。新增装备先明确新体验，避免只加数值等级。2026-10-05 的 v0.15.0 候选扩为八枪、六钓具，保持三种弹药；下方六枪五竿资料是保留的原装备规范。

## v0.15.0 装配与新增装备

- 双联回形针霰弹枪用铜色短双管和折装动作；批注半自动步枪用浅绿长机身与独立弹匣；团建抛网用紫色网框、镂空网格和分段拉回动作。
- 两种互斥核心与独立辅助附件在第一/第三人称可见。相同装备ID换装也更新外形，不能只在换枪时重建；基础模型缓存不含玩家专属附件，活动零件不并入不可变网格。
- 附件不能遮住正常瞄准中心；换弹中切走再切回必须恢复机身、弹匣与折装原点。网格保持真实细厚度和开口，避免密集共面闪烁或不透明片面。
- 抛网的实际状态、手势、岸边网格、鱼影和侧边提示一致；落水前不画水上网，收网时逐步收拢，第二条鱼上岸位置不能与第一条重叠。

## v0.10.0补充：场景和特效也遵守同一规则

- 重面扫描包含完整场景组装：箱体与事件标记、建筑与基础/加固、门的开合、受损姿态、第一/第三人称搬运，不能只检单个附件。
- 刚体表面弹痕归实际可见支撑物所有，随晃动/旋转，支撑销毁或形态更换立即清除。缺失支撑不退化为悬空世界贴片；活体、水面和空气分别使用短时反馈。
- 连续命中同一位置去重，弹痕、颗粒和碎片有全局数量与时长上限；重入房间清理旧特效。
- 昼夜光照只由连续时钟更新。水位、阶段提示或网络快照不能交替重写灯光。
- 动作相位不能直接阶梯式使用低频网络倒计时；局部动画要按本地帧平滑，并检查状态切换及动画复位。
- 网页运行时合并基础网格可能触发显卡缓冲区同步读回。固定种类装饰在加载期生成、实际绘制并缓存不可变网格；游戏中创建独立节点复用资源，不共享碰撞、业务标识、受击材质或动画状态。远处搜集物按帧预算补齐外观，靠近可交互目标必须先确保可见。
- 新增内容的性能检查包含首次进入白天生成场景，不能只测已加载完成的平稳时段。缓存还要检查实例独立性、源对象销毁后复用、取消加载和再次进入。
- 操作提示必须对应当前状态真正可执行的输入；等待咬钩不能提前提示起竿，稀有标题可以提前预告，操作文案仍随阶段切换。
- 新增交易按钮要在真实布局中测量最终矩形，覆盖启用/禁用与滚动。只设置最小尺寸不足以阻止容器纵向拉伸。

## 几何和导入门槛

- 相接零件不能存在不同颜色、同向、同平面且有面积交叠的外露表面。帽沿、枪壳、包覆件、枪栓、瞄具都适用。合批不会消除重面。
- 通过真实几何厚度、外扩或内收修复；不靠全局关闭深度、透明排序或调相机掩盖。固定配件必须与机身连接，活动件在静止、射击、换弹、换回后的状态都恢复到正确原点。
- Blender 外置 `.bin` 的色彩或几何变化必须更新 `.gltf` 中的 buffer SHA 标记。导入后检查 Godot 实际网格，不能只证明源文件已复制。
- 导出每件保持低面数、单表面单材质、无贴图；原生程序化模型和旧竿保持当前预算。新增动画不无上限地产生粒子或材质实例。
- 运行 `tools/testing/check-gltf-coplanar.mjs` 检查全部导出资产；用 `dump-runtime-geometry.gd` 和 `analyze-runtime-coplanar.mjs` 检查实际组装模型。检查不同顶点三角形的真实交叠，不能只查完全重复的面。
- 固定机位和移动机位查看六枪、五竿、四肤色头部、快捷物品；保留修前失败和修后结果。内部重面若保留，必须证明整个交叠区域在全部正常动画中被封闭实体覆盖。

## 玩法、文案与验证

开镜进入时间、换枪可射击时间、移动散布由配置及权威模拟决定，UI 准星和动画匹配实际规则。退出开镜和切到鱼竿/空手应立即恢复正常视野。手枪单击；霰弹显示每弹丸伤害 × 数量；泵动与拉栓不标成普通自动枪。按钮、固定外框、两侧 HUD 继续遵循现有 UI 规范。

每轮必须覆盖：六枪开镜/射击/换弹/切换、五竿完整收线及上岸、旧满弹存档恢复、三弹种守恒；相关规则、虚拟玩家昼夜循环、两浏览器联机与最终包多人性能。性能样本独占测量窗口，报告真实渲染客户端数，不能将同机机器人等同于多台公司电脑。

设计方法参考：[Riot 武器设计文章](https://playvalorant.com/en-us/news/dev/how-the-valorant-arsenal-was-built/) 的场景取舍和轮廓辨识原则；深度争用参考 [Godot 渲染限制](https://docs.godotengine.org/en/4.7/tutorials/3d/3d_rendering_limitations.html)。

## v0.9.3：交互差异的验收原则

每件核心道具都应回答三个问题：玩家观察什么、下一次操作怎样选择、不同选择怎样改变结果。颜色、动画幅度和奖励倍率只能辅助，不能独自证明新增玩法。扩展怪物与破坏物时同样采用此原则；先确认行为取舍，再增加数量。

五竿分别强调等漂、轻拉停顿、侧移换角、冲刺卸力、扫底解卡。保留通用蓄力抛竿和张力收线，让玩家学会一种之后能理解其他种；不把每根竿都变成必须盯着文字完成的小游戏。未采用最佳策略仍应有宽容的可完成路径，高手策略要经相同钓获、相同时间条件的对照验证。

第一人称、队友动作、水面目标、音效和侧栏提示共用权威阶段和连续动作相位。松手停卷轮，冲刺放线，竿尖弯曲后鱼线仍接在竿尖；不得以绝对时间乘可变频率制造相位跳跃。鱼线和水面节点数量有界，取消、换装、离线和再次抛竿必须复位。私有钓获结果不提前泄漏给客户端。

验收增加五竿真实完整流程、正确/错误操作对照、仅转镜头与实际侧移的区分、磁吸卡住后停顿/侧移两种解法、转移已装备鱼竿时中断、第一/第三人称连续姿态，以及八人同时钓鱼和取消后的节点回收。多人性能另测，不用单人录屏或无渲染机器人代替。
